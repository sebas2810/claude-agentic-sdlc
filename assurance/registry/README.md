# The Agent Registry — know your agent

One [agent card](AGENT-CARD.template.md) per seat, across **all three loops** — delivery, ops, and the Auditor itself. The registry is three audit artifacts in one: the **asset inventory** (ISO 27001 5.9: agents in the register), the **non-human-identity register** (each seat = a sponsored service identity with an owner and a scope), and the **evidence pack** external auditors and AI insurers now request up front.

Rules:

- **A card per seat, no exceptions** — including the Auditor (the third line is in scope for the third line).
- **Cards state effective reality, not intent**: the model tier actually configured, the credentials actually held (and their scopes), the tools/MCP servers actually reachable. The quarterly engagement **reconciles cards against live credentials** — a card underselling a seat's actual permissions is a *critical* finding (that's the shadow-capability failure), overselling is a hygiene finding.
- **A card changes in the same PR as the change it describes** — a new tool, a scope change, an autonomy grant lands with its card update or it doesn't land.
- **Sponsor named** — every seat has one accountable human (the owner, for a single-operator instance). Deprovisioning is part of the card: when a seat is retired, its credentials are revoked and the card is archived with the date, not deleted.
